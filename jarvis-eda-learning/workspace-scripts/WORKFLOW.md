# Unified Cell Creation Workflow

Applies to: bias network, LPF, SPDT — and any future cell type.

---

## Pipeline

```
Step 1   .net input
Step 2   Pre-process
Step 3   PDK translation    (optional)
Step 4   Create ADS cell
Step 5   Hierarchy
Step 6   Simulation template
```

---

## Step 1 — .net Input

All cell types enter the pipeline via a `.net` file.

| Cell type     | Source                                                        |
|---------------|---------------------------------------------------------------|
| Bias network  | Generated by script (simple RC topology, no PDK needed)      |
| LPF           | External netlist from topology study                         |
| SPDT          | External netlist from topology study                         |

The `.net` format is the rfscikit standard netlist (see `skills/ads-netlist-translator/`).

---

## Step 2 — Pre-process

Parse the `.net` file. Extract:
- Component list (type, value, instance name)
- Net connectivity (which pins connect to which nets)
- Port/pin definitions

Output: structured component and connectivity data ready for Step 3 or 4.

Scripts: `net_parse.py`, `net_prepare.py`

---

## Step 3 — PDK Translation (optional)

Substitute generic schematic components with PDK-specific cells.

| Cell type     | Required?  | Notes                                       |
|---------------|------------|---------------------------------------------|
| Bias network  | No         | Uses generic `ads_rflib:R` and `ads_rflib:C` |
| LPF           | TBD        |                                             |
| SPDT          | Yes        | FETs → WIN_PP1029_CPW via `@PDK_SWAP` tags  |

PDK mapping rules live in `pdk-configs/WIN_PP1029_core.yaml`.

---

## Step 4 — Create ADS Cell

Build the schematic cell using the `de_` API confirmed from ADS `.dem` macro recordings.

**API pattern (ground truth from .dem):**

```python
# Create schematic
de.de_create_new_schematic_view(lib, cell, "schematic")
ctx = de.de_get_design_context_from_name("lib:cell:schematic")

# Place component
item = de.de_init_item("ads_rflib:R:symbol")
de.de_place_item(item, x, y)

# Rotate before placing (C shunt, GND)
item = de.de_init_item("ads_rflib:C:symbol")
de.de_rotate_inc()
de.de_place_item(item, x, y)

item = de.de_init_item("ads_rflib:GROUND:symbol")
de.de_rotate_image("DOWN")
de.de_place_item(item, x, y)

# Create generic pin (not simulation Term)
de.db_create_pin(ctx, x, y, rotation, de.db_layerid(229), 0, "pin_name", 2)

# Wire
de.de_connect()
de.de_add_wire(x1, y1)
de.de_add_wire(x2, y2)
de.de_end()

# Set component parameter to reference design variable
item = de.de_edit_item("R1")
de.de_set_item_parameters(item, [de.prm_ex("ads_rflib", "StdForm", "Rs Ohm")])
de.de_end_edit_item(item)

# Set design variables with defaults
de.de_update_item_ex(ctx, [
    de.create_parm("Rs", "", 68608, "StdFormSet", -1,
                   de.prm_ex(lib, "StdForm", "1000"), None),
])

# Save
de.de_save_oa_design("lib:cell:schematic")

# Auto-generate blackbox symbol
source = de.de_get_design_context_from_name("lib:cell:schematic")
sym    = de.de_create_new_symbol_view()
de.de_generate_blackbox_symbol(sym, source, 0.25, 0.25,
                               True, True, 0, False, "dot",
                               False, False, False)
```

**Cell conventions:**
- Library: `spdt_switch_pdk_lib` (existing workspace library — never create a new library)
- Cell naming: `cell_<type>_<description>` (e.g. `cell_fetbias_switch_gate`, `cell_lpf_input`)
- I/O connections: generic pins via `db_create_pin` — **not** simulation `Term` components
- Tunable values: always exposed as design parameters, never hardcoded
- Symbol: always auto-generated via `de_generate_blackbox_symbol`

**Reference implementation:** `workspace-scripts/ads_bias_subcell_create.py`
LPF and SPDT cell creator scripts will follow this same pattern.

---

## Step 5 — Hierarchy

Cells can instantiate sub-cells. The same `de_init_item` + `de_place_item` pattern is used,
referencing the sub-cell by its LCV name:

```python
inst = de.de_init_item("spdt_switch_pdk_lib:cell_fetbias_switch_gate:symbol")
de.de_place_item(inst, x, y)
```

Example: the SPDT top-level cell will instantiate one `cell_fetbias_switch_gate` per FET.

---

## Step 6 — Simulation Template

A separate simulation template cell brings in the top-level DUT cell and adds:
- Simulation `Term` components for ports
- DC/RF sources
- Sweep and analysis settings

Simulation setup is **never baked into the circuit cell itself** — the cell must be
reusable across different simulation contexts (S-param, large-signal, DC sweep, etc.).
