## Issue 1: Replace Simulation Ports with Generic Pins

**Problem:**
```python
port_ctrl = design.add_instance(de.LCVName("ads_simulation", "Term", "symbol"), ...)
port_gate = design.add_instance(de.LCVName("ads_simulation", "Term", "symbol"), ...)
```
`ads_simulation:Term` symbols are **only for top-level simulation**. When this cell is instantiated as a sub-circuit in a parent schematic, Terms don't work as interconnect points. The parent schematic needs generic **pins** (circuit interface terms).

**Solution:**
```python
from keysight.ads.de._pde.db import TermType

net_ctrl = design.find_or_add_net("v_ctrl")
term_ctrl = design.add_term(net_ctrl, "v_ctrl", TermType.INPUT_OUTPUT)

net_gate = design.find_or_add_net("sw_gate")
term_gate = design.add_term(net_gate, "sw_gate", TermType.INPUT_OUTPUT)
```

**Result:**
- Two circuit interface terms created: `v_ctrl`, `sw_gate`
- These are proper pins that can be connected to wires in parent schematics
- TermType.INPUT_OUTPUT allows bidirectional (though for this bias cell, they're uni-directional in practice)

## Issue 2: Add Blackbox Symbol Generation

**Problem:**
The `.dem` reference code mentioned:
```
de_generate_blackbox_symbol(new_symbol, source_design, ...)
```
This function doesn't exist in the public `keysight.ads.de` Python API.

**Solution:**
Create an empty symbol view; user populates it manually or via ADS GUI auto-generation:
```python
if cell.view_exists(SYMBOL):
    cell.delete_view(SYMBOL)

symbol_view = de.View.create(cell, SYMBOL, "schematicSymbol")
```

**Result:**
- `symbol` view created in the cell
- Currently empty (no geometry)
- ADS GUI can auto-generate using schematic pins as a starting point
- Alternative: Write a separate symbol geometry generator (not in scope here)

**Note:** The Python API can create empty views but lacks the procedural symbol generator that the AEL Tcl code had. This is acceptable for now; the symbol can be:
1. Auto-generated via ADS GUI (Edit → Generate Symbol)
2. Manually created in the Symbol Editor
3. Generated by a future AEL/Python symbol generator script

## CRITICAL FIX: Design Persistence

### Root Cause
Instances and wires were created in memory but **never written to disk**. When the workspace was closed and reopened, the schematic appeared empty.

### Discovery Process
1. First attempt: Added instances directly, called no explicit save → Data lost
2. Second attempt: Wrapped in `tx = de.db.Transaction(...)` with `tx.commit()` → Still lost, design became read-only
3. **Root finding:** Checked `sch_view.get_design()` signature and found:
   ```python
   get_design(mode: DesignMode = DesignMode.READ_ONLY) -> Design
   ```

### Solution
**Open design in WRITE mode and explicitly save:**
```python
from keysight.ads.de._pde.db import DesignMode

design = sch_view.get_design(DesignMode.WRITE)

# ... add instances, wires, nets, variables ...

design.save_design()  # CRITICAL: Persists all changes to disk
```

### Why This Was Critical
- **Default:** `DesignMode.READ_ONLY` → Can read and traverse, but cannot persist writes
- **Attempted save:** Raises `RuntimeError: Attempt to save a read-only design`
- **No error on add_instance():** Silently fails to persist; changes only exist in memory

### Verification
After implementing the fix:
- ✅ All components persisted: C1, R1, GND

- ✅ All parameters saved: Rs=1000 Ohm, Cp=1 pF

## Key Learnings

1. **DesignMode matters:** Always open designs with `DesignMode.WRITE` for editing
2. **save_design() is critical:** Changes don't persist automatically; must call explicitly
3. **Transactions vs direct API:** Direct `add_instance()` + `save_design()` more reliable than transaction pattern in ADS 2026
4. **Terms vs Ports:** 
   - `ads_simulation:Term` = top-level simulation interface
   - `design.add_term()` = sub-cell circuit interface (what we need)
5. **Symbol generation:** Python API lacks the procedural symbol generator; UI or alternative tools needed
